# Работа с Visual Studio

Visual Studio — лучший инструмент для работы с репозиторием. Большинство функций инструмента работают корректно, но есть несколько особенностей, которые следует учитывать:

## Обозреватель тестов (Test Explorer)

Вы можете запускать тесты через **Обозреватель тестов**, но для этого потребуется настроить несколько параметров:

-   Включите `Автоматическое обнаружение файлов runsettings` (`Test Explorer window -> Settings button -> Options`). Параметры тестов (например, какой хост `dotnet` использовать) сохраняются в автоматически сгенерированном файле `.runsettings`, и важно, чтобы Visual Studio использовал его.
-   Установите `Архитектуру процессора для проектов AnyCPU` в значение `Авто` (`Test Explorer window -> Settings button -> Processor Architecture for AnyCPU project`).
-   Можно отключить/включить `Обнаружение тестов в реальном времени из исходных файлов C# и VB.NET` (`Test explorer window -> Settings button -> Options -> Discover tests in real time from C# and Visual Basic .NET source files`):
    -   Может быть полезно оставить параметр включённым, если вы активно пишете новые тесты и хотите видеть их в **Обозревателе тестов** без предварительной сборки.
    -   Отключите, если вы в основном запускаете существующие тесты, особенно с условными атрибутами. Многие модульные тесты используют атрибуты, такие как `[SkipOnTargetFramework]`, указывающие, что тест актуален только для определённых конфигураций. Поскольку функция обнаружения в реальном времени пока не учитывает эти атрибуты, тесты могут отображаться в **Обозревателе тестов** некорректно, а при запуске — завершаться с ошибкой или зависать.
-   Можно отключить/включить `Параллельный запуск тестов` (`Test Explorer window -> Settings button -> Run tests in Parallel`).
    -   Включите, если тесты выполняются медленно или их много.
    -   Отключите, если нужно упростить отладку или просмотр вывода отладки.

Если при запуске тестов в Visual Studio возникают неожиданные проблемы, сначала проверьте указанные выше настройки, убедитесь, что тесты корректно работают из командной строки, а также что используется последняя версия Visual Studio. Для диагностики можно включить детальное логирование (`Test explorer window -> Settings button -> Options > Logging Level: Trace`) — это может помочь выявить причину или предоставить дополнительную информацию для анализа.

## Запуск с отладкой (F5)

В dotnet/runtime используется `dotnet test` ([VSTest](https://github.com/Microsoft/vstest)), который порождает дочерние процессы при выполнении тестов.  
По умолчанию Visual Studio не отлаживает дочерние процессы автоматически, поэтому для поддержки отладки через **F5** требуются дополнительные шаги.  
(Примечание: эти шаги не нужны для работы **Обозревателя тестов**.)

1. Установите расширение [Microsoft Child Process Debugging Power Tool](https://marketplace.visualstudio.com/items?itemName=vsdbgplat.MicrosoftChildProcessDebuggingPowerTool).
2. Перейдите в настройки отладки дочерних процессов (`Debug -> Other Debug Targets -> Child Process Debugging Settings...`), включите опцию `Enable child process debugging` и сохраните изменения.
3. Перейдите в настройки отладки проекта (`Debug -> $ProjectName Properties`) и включите опцию `Enable native code debugging`.
