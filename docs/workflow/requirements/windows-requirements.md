# Требования для Windows

Чтобы собрать репозиторий на _Windows_, необходимо установить _Visual Studio_, а также дополнительные инструменты, которые представлены и описаны ниже.

## Инструменты и конфигурация

### Git для Windows

-   Скачайте и установите [Git для Windows](https://git-scm.com/download/win) (требуется версия 2.22.0 и выше).

-   Установщик по умолчанию должен добавить `Git` в вашу переменную среды `PATH`. Или иметь специальный флаг во время установки для этой операции. Если по какой-либо причине `Git` не быд добавлен, следуйте [инструкции ниже](#setting-environment-variables-on-windows).

### Длина пути

Сборка репозитория также требует снятия ограничения длины пути как в системе Windows, так и в _Git_. Чтобы настроить их в Git, откройте терминал с правами администратора и введите следующую команду:

```powershell
git config --system core.longpaths true
```

Это операция необходима, потому что _Git для Windows_ скомпилирован с использованием **MSYS**, который использует версию Windows API с ограничением длины пути в 260 символов, в отличие от обычного ограничения в 4096 символов на macOS и Linux.

Далее, чтобы снять ограничение длины пути в Windows, следуйте инструкциям [по этой ссылке](https://learn.microsoft.com/windows/win32/fileio/maximum-file-path-limitation?tabs=registry#enable-long-paths-in-windows-10-version-1607-and-later).

Если ограничение не будет снято, вы можете столкнуться с проблемами при попытке клонировать репозиторий. Например, при клонировании или работе с библиотеками вы можете получить ошибку `Unable to create file: Filename too long`.

### Visual Studio

Скачайте и установите последнюю версию [Visual Studio](https://visualstudio.microsoft.com/downloads/) (требуется версия 2022-17.8 и выше). Версия **Community Edition** доступна бесплатно. Более старые версии могут успешно собрать проект, однако, IDE может может сообщать о несоответствии диагностики в окне _Errors and Warnings_. Поэтому рекомендуется использовать последнюю публичную версию Visual Studio, так как это решает проблемы с диагностикой и ожидаемыми результатами, а также обеспечивает корректную работу IDE.

Обратите внимание, что Visual Studio и ее инструменты разработки необходимы, независимо от того, планируете ли вы использовать этот IDE или нет.

#### Рабочие нагрузки

Настоятельно рекомендуется использовать _Рабочие нагрузки_ (_workloads_), так как этот подход устанавливает пакеты, которые включают все необходимые инструменты для корректной работы репозитория. Откройте _Visual Studio Installer_ и нажмите _Изменить_ (_modify_) во время установки Visual Studio. Затем перейдите на вкладку _Рабочие нагрузки_ (обычно выбрана по умолчанию) и установите следующие пакеты:

-   .NET desktop development
-   Desktop development with C++

Чтобы собрать тесты и заниматься разработкой для ARM32/ARM64 архитектур, вам понадобятся дополнительные компоненты. Вы можете найти их, нажав на вкладку _Индивидуальные компоненты_ (_individual components_) в _Visual Studio Installer_:

-   Для ARM :
    -   MSVC v143 - VS 2022 C++ ARM64/ARM64EC build tools (Latest) для Arm64
    -   MSVC v143 - VS 2022 C++ ARM build tools (Latest) для Arm32.
-   Для сборки тестов: _C++/CLI support for v143 build tools (Latest)_

Кроме того, в корне репозитория runtime также включен файл `.vsconfig`, который содержит все необходимые компоненты в формате JSON. Вы можете запустить Visual Studio напрямую и импортировать [этот файл .vsconfig](https://learn.microsoft.com/visualstudio/install/import-export-installation-configurations?view=vs-2022#import-a-configuration) вместо того, чтобы устанавливать рабочие нагрузки самостоятельно. Однако стоит отметить, что предоставленный файл может устареть и не содержать важных компонентов. Поэтому рекомендуется проверить, установлены ли все рабочие нагрузки.

#### Индивидуальные инструменты разработки

На этом этапе все необходимые инструменты должны были быть установлены вместе с Visual Studio. Однако некоторые из этих инструментов могли не установиться. В таком случае вы можете установить эти инструменты самостоятельно из других источников. Установщики этих инструментов должны автоматически обновить переменную среды `PATH`. Если вы пропустили эту опцию или предпочитаете настроить их позже самостоятельно, вы можете следовать инструкциям [ниже](#setting-environment-variables-on-windows).

Вот ссылки, по которым вы можете скачать нужные инструменты:

-   _CMake_: https://cmake.org/download (версии 3.20 и выше)
-   _Ninja_: https://github.com/ninja-build/ninja/releases (рекомендуется самая свежая версия)
-   _Python_: https://www.python.org/downloads/windows (версии 3.7.4 и выше)

**ПРИМЕЧАНИЕ:** Если вы планируете использовать _MSBuild_ вместо _Ninja_ для сборки нативных компонентов, то рекомендуется использовать версию CMake 3.21 и выше. Это связано с тем, что генератор VS2022 не присутствует в CMake до указанной версии.

### Powershell

Репозиторий также использует некоторые скрипты `powershell` в процессе сборки для Windows, поэтому убедитесь, он добавлен переменную среды `PATH`. Он находится по адресу `%SYSTEMROOT%\System32\WindowsPowerShell\v1.0` и должен быть настроен до начала работы с репозиторием.

Минимально требуемая версия powershell - `3.0`. Проверьте версию, используя команду `$PSVersionTable.PSVersion` в терминале powershell.

### .NET SDK

Наличие .NET SDK не является необходимым для сборки или тестирования этого репозитория, но его установка позволяет вам просматривать файлы решений в кодовой базе с помощью Visual Studio и использовать команду `dotnet.exe` для сборки и запуска .NET приложений.

SDK используется в следующих инструкциях:

-   [Сборка тестов с помощью установленном SDK](testing/using-your-build-with-installed-sdk.md)
-   [Сборка тестов с помощью dev shipping packages](testing/using-dev-shipping-packages.md)

Требуемая версия SDK представлена в файле [global.json](https://github.com/dotnet/runtime/blob/main/global.json#L3). Вы можете найти night-билды и бинарные файлы для последних версий в [репозитории SDK](https://github.com/dotnet/sdk#installing-the-sdk).

Если вы хотите избежать изменения состояния вашей машины, вы можете использовать локально установленный SDK из репозитория, передав решение для загрузки с помощью переключателя `-vs`. Например:

```cmd
.\build.cmd -vs System.Text.RegularExpressions
```

Эта команда обновит переменные среды `DOTNET_ROOT` и `PATH`, указывая на локально установленный SDK в директории `.dotnet`, который находится в корне репозитория, но только на время текущей сессии терминала. Затем будет запущен экземпляр Visual Studio, зарегистрированный под расширение `.sln`, а также откроется решение, которое вы передали в качестве аргумента командной строки.

## Установка переменных среды

Как упоминалось в предыдущих разделах, команды, запускающие инструменты разработки, должны находиться в переменной среды `PATH`. Обычно их установщики имеют опцию автоматической настройки, включенную по умолчанию, но если по какой-либо причине вам нужно установить их самостоятельно, следуйте инструкции ниже.

Переменные можно установить для текущей сессии терминала или установить их непосредственно в систему, чтобы сделать их постоянными.

**Добавить переменные для текущей сессии**

Откройте _Командную строку_ и выполните следующую команду:

```cmd
set PATH=%PATH%;<path_to_directory_you_want_to_add>
```

Или выполните команду из _Powershell_:

```powershell
$Env:PATH += ";<path_to_directory_you_want_to_add>"
```

**Добавить переменные в систему Windows**

Чтобы добавить переменные в систему Windows, откройте _Панель управления_. Далее пройдите в _Система и безопасность_ -> _Система_ -> _Дополнительные параметры системы_ -> _Переменные окружения_ (System and Security->System->Advanced System Settings->Environment Variables). Найдите переменные среды `PATH`: одна в разделе `Переменные пользователя` (_user variables_) и одна в разделе `Системные переменные` (_system variables_). Если вы хотите сделать изменения постоянными только для текущего пользователя, отредактируйте первый раздел, а если хотите, чтобы они распространялись на все учетные записи на этом компьютере, отредактируйте второй раздел.
